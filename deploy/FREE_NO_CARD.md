# Deploy RentManager with no card and no bill

Every service here is free, needs **no credit card**, and is run by real
companies in production. Nothing in this path expires into a bill.

| Piece | Service | Free limits that matter |
|---|---|---|
| API (Spring Boot) | **Render** web service, Docker | 512 MB RAM, 0.1 CPU, 750 instance-hours/month (enough for one always-on service), sleeps after 15 min idle unless pinged |
| Database | **Neon** Postgres | 0.5 GB storage, wakes from idle in under a second, no expiry |
| Web app (Next.js) | **Netlify** | 100 GB bandwidth, 300 build minutes/month, commercial use allowed |
| Keep-awake ping | **cron-job.org** | every 10 minutes, free |
| Encrypted off-site backups | **GitHub Actions** (`.github/workflows/backup.yml`) | nightly, kept 90 days |
| Sign-in | **Clerk** development instance | **100 users total** — read §7 before you grow |
| Android app | **EAS Build** free plan | 15 Android builds a month |
| Push notifications | **Expo** | free |
| Uptime alerts | **UptimeRobot** | 5-minute checks |

Domains are the ones the platforms give you: `*.onrender.com` and
`*.netlify.app`, both with HTTPS included.

> **Why not Render's own free Postgres?** It is deleted 30 days after creation.
> Neon's free database has no expiry.

---

## 1. Database — Neon (10 min)

1. Sign up at neon.com with GitHub. No card.
2. Create a project in the region closest to Kenya (Frankfurt or Singapore).
3. Copy the connection string. It looks like
   `postgresql://user:password@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`.
4. Split it into the three values the API wants by running
   `./deploy/neon-to-env.sh` and pasting the string when asked (input is
   hidden). It prints `DB_URL` (a `jdbc:` URL with no credentials in it),
   `DB_USERNAME` and `DB_PASSWORD`.

**Check:** Neon's SQL editor answers `select 1`.

## 2. API — Render (20 min, mostly building)

1. Sign up at render.com with GitHub. No card. Give it access to
   `rentmanager-backend`.
2. **New → Blueprint** and pick the repo. It reads `render.yaml`: a free Docker
   web service in Frankfurt, health check `/api/v1/public/mobile/config`.
3. Fill in the values Render asks for (none of them are committed):
   - `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` from step 1
   - `CLERK_JWKS_URL`, `CLERK_SECRET_KEY`, `CLERK_WEBHOOK_SECRET` from step 4
   - `CORS_ALLOWED_ORIGINS` = your Netlify URL (step 5 — come back for it)
   - `DARAJA_CREDENTIALS_ENCRYPTION_KEY` — run `./deploy/gen-secrets.sh` once
     and take it from there. **Keep a copy in your password manager. Lose it
     and landlords' stored M-Pesa credentials can never be read again.**
   - `JWT_SECRET` is generated by Render itself.
4. The first deploy takes 10–20 minutes: it builds the image and runs the
   database migrations. If the app refuses to start, the logs name every unsafe
   setting, one per line.

**Check:** `https://<your-api>.onrender.com/api/v1/public/mobile/config` returns
JSON, and `/api/v1/users/me/access` returns 401.

### Real client IPs on Render

The public "reserve a unit" endpoint limits M-Pesa prompts per phone **and per
IP**. Behind Render's proxy, every request looks like it comes from the proxy
unless the app is told which addresses to trust. After the first deploy:

1. Open the logs and note the address requests arrive from (`X-Forwarded-For`).
2. Set `TRUSTED_PROXIES` to a regex matching that range, for example
   `10\.\d{1,3}\.\d{1,3}\.\d{1,3}|100\.2[0-9]\.\d{1,3}\.\d{1,3}`.

Never set it to `.*`: a caller could then forge the header and get a fresh
limit bucket per request. Until you set it, the per-phone limit still holds.

## 3. Keep it awake — cron-job.org (5 min)

**This step is not optional.** Measured on 2026-09-16 in a container limited to
exactly Render's free resources (512 MB, 0.1 CPU):

| | Measured |
|---|---|
| Cold start (image start → serving, including 97 migrations) | **528 s (8.8 min)** |
| Memory once running | 336 MB of 512 MB |
| Warm response, public endpoints | 13–100 ms |
| First request to a path (class loading) | 1.0–1.4 s |

So the app runs comfortably on the free tier, but waking from sleep takes about
nine minutes — not the 30–60 seconds Render quotes for lighter runtimes. A
sleeping service would miss M-Pesa callbacks (Safaricom gives up in seconds) and
stall the scheduled notification sweeps. Keep it awake and it never cold-starts
except on deploy.

1. Sign up at cron-job.org (free, no card).
2. New cron job → URL
   `https://<your-api>.onrender.com/api/v1/public/mobile/config`, every
   **10 minutes**.

750 free instance-hours a month covers one service running all month (744
hours), so this stays inside the free tier — but do not run a second always-on
free service in the same Render account.

**Check:** the job history shows 200s and Render's metrics show no spin-downs.

**Deploying costs ~10 minutes of downtime** on the free plan (no rolling
restart, plus that cold start). Deploy late at night, and expect the same after
any Render-side restart.

## 4. Sign-in — Clerk (15 min)

Follow [README.md §3](README.md) using a **development** instance, with these
URLs:
- Backend webhook: `https://<your-api>.onrender.com/api/v1/webhooks/clerk`
- Web webhook: `https://<your-site>.netlify.app/api/webhooks/clerk`
- Allowed origin: `https://<your-site>.netlify.app`

## 5. Web app — Netlify (15 min)

1. Sign up at netlify.com with GitHub. No card.
2. **Add new site → Import from Git →** `rentmanager-frontend`. It reads
   `netlify.toml`.
3. Site settings → Environment variables:
   - `BACKEND_URL` = `https://<your-api>.onrender.com`
   - `NEXT_PUBLIC_API_URL` = `https://<your-site>.netlify.app/api/v1`
   - `NEXT_PUBLIC_APP_URL` = `https://<your-site>.netlify.app`
   - `NEXT_PUBLIC_APP_ENV` = `production`
   - `NEXT_PUBLIC_APP_NAME` = `RentManager`
   - `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`,
     `CLERK_WEBHOOK_SIGNING_SECRET`
4. Deploy, then set Render's `CORS_ALLOWED_ORIGINS` to the Netlify URL.

The browser calls `/api/v1` on the Netlify domain and Netlify forwards it to
Render, so the security policy stays same-origin and there is no CORS.

**Check:** the site loads over HTTPS, `/api/v1/public/mobile/config` on the
Netlify domain returns JSON, and `/dashboard` sends you to sign-in.

## 6. Backups (10 min — do not skip)

In `rentmanager-backend` → Settings → Secrets and variables → Actions, add:
- `BACKUP_DATABASE_URL` — the Neon connection string from step 1
- `BACKUP_PASSPHRASE` — from `./deploy/gen-secrets.sh`, **kept in your password
  manager**

Then run **Actions → Database backup → Run workflow** once by hand. It dumps the
database, encrypts it, decrypts the copy again to prove it is readable, and
keeps it for 90 days. Restore instructions are at the top of the workflow file.

Neon's free plan also keeps its own 6-hour restore window.

## 7. The first real limit: 100 users

A Clerk development instance stops at **100 users**, and renters count too:
three landlords with 30 renters each will reach it. A Clerk production instance
is free up to 50,000 monthly users, but it needs a domain you control.

- **Free route:** apply for a `.eu.org` domain (free, approval takes days) or a
  `js.org` subdomain, manage DNS with Cloudflare (free), and point Clerk at it.
  Netlify and Render both accept custom domains on their free plans.
- **Paid route:** a `.co.ke` domain is about KSh 1,000–1,500 a year — the first
  thing worth spending money on.

## What this path does not give you

- **No redundancy.** One instance: a deploy or a Render-side restart is a
  ~9-minute outage (measured). Acceptable before you have paying landlords,
  not after.
- **0.1 CPU.** Measured fine warm (13–100 ms), but every deploy or restart is a
  ~9-minute outage, and heavy traffic will crawl. The fix is money (Render
  Starter, about US$7 a month) or a free student-credit VM.
- **No iOS.** Apple charges US$99 a year, so Android only for now.
- **No SMS.** It is charged per message, so the apps rely on free push
  notifications.

## When there is money, spend it in this order

1. A domain — unlocks 50,000 free Clerk users and looks credible: ~KSh 1,500/yr.
2. Render Starter for the API, or any small VPS: ~US$7/month, removes the CPU
   and sleep limits.
3. Google Play developer account: US$25 once.
4. Anything else.
